# Авторизация по номеру телефона

## Сценарий

1. Приложение пытается восстановить сохранённую сессию. Шлюз должен подтвердить её действительность.
2. При отсутствии сессии пользователь выбирает страну и вводит номер. libphonenumber проверяет номер и преобразует его в E.164; расширения номера не принимаются.
3. `requestCode` возвращает `AuthChallenge`: непрозрачный идентификатор, нормализованный телефон, длину кода, время истечения и время следующего разрешённого запроса.
4. Пользователь вводит код. `verifyCode` передаёт его шлюзу, а репозиторий сохраняет успешную сессию перед переходом на следующий экран.
5. Повторная отправка заменяет challenge. Предыдущий код больше не должен приниматься. Возврат к номеру не обнуляет время ожидания.

QR-сценариев нет. Длина кода и интервалы MAX не зашиты в UI. Если реальное API требует дополнительную проверку, адаптер должен явно вернуть неподдерживаемый этап до его реализации, а не считать вход успешным.

## Контракт адаптера

Методы `MaxAuthGateway` — внутренний контракт приложения. Они не являются именами HTTP-методов или SDK MAX. Форматы, протокол и семантика ошибок уточняются по документации программы Open Client API.

Адаптер сопоставляет сетевые ошибки с `NETWORK`, ограничения — с `RATE_LIMITED` и сроком ожидания, неверный/просроченный код — с соответствующими ошибками. Настоящие ограничения на попытки обеспечивает MAX; клиентский таймер служит для интерфейса.

## Хранение

`KeystoreSessionStore` шифрует данные AES-256-GCM. Ключ создаётся Android Keystore; для каждой записи генерируется новая IV. Сохраняется только шифротекст в `Context.noBackupFilesDir`, запись выполняется через AtomicFile. Резервное копирование приложения отключено. OTP, challenge и номер телефона не сохраняются вместе с сессией.

Нельзя журналировать телефон, код, challenge или credential. Методы `toString()` чувствительных моделей скрывают содержимое. Формат credential пока непрозрачен: это не предположение о том, что MAX использует именно bearer token.

Выход пытается завершить удалённую сессию и очищает локальное хранилище независимо от результата удалённого запроса. При временной ошибке проверки сохранённая сессия не удаляется; при подтверждённом истечении — удаляется.

## Демо

Демо не отправляет SMS и не подключается к MAX. Код `12345`, срок 5 минут, повторный запрос через 30 секунд, максимум 5 неверных попыток на challenge. Успешный код однократный. Эти параметры используются только для разработки и тестов.
